For every row record expected result, observed result, status, evidence filename,

P01 STARTUP AND CONTROL
Start a new test run. Confirm the intended map is rendered and the player can
look around and move. Observe for loading failures, obvious rendering errors
and input capture problems. Process activity alone is not sufficient.

P02 STAIR AND RAILING ROUTE
Reach the originally marked landing using normal controls. Capture the opening
and adjacent rails. Walk through it, down the intended stairs and back up without
jumping past obstructions. Repeat with angled approaches and normal run input.
Pass requires no snag, unexpected fall or rescue teleport. Keep the platform
and genuine drop-edge protection intact. Record a continuous video if supported;
otherwise use checkpoint captures and an explicit manual observation record.

P03 TERMINAL AND INSPECTION INPUT
Raise/stow the terminal. Verify readable text, targeting and the normal PASS/FLAG
controls. Try an invalid target and repeat a log action; required completion
counts must not inflate. Capture the visible response and checklist updates.

P04 TWO NORMAL ROUNDS
Complete two rounds by walking, inspecting and using normal inputs. Test one
incomplete/incorrect submission and the intended recovery before finishing.
Verify a round advances once and required state resets correctly. Do not set
LogResult, CurrentRound or completion flags through tools to claim this pass.

P05 AIRLOCKS
Check the intended locked condition and unlocked transit in both directions.
Verify safe arrival and no repeated bounce between gates. Record the conditions
under which each result occurred, including completed fixture requirements.

P06 SAVE AND RESUME
Use the actual supported save/checkpoint flow after meaningful progress. Record
the round, relevant checklist/anomaly state and player location. Quit normally,
relaunch the same build, resume, and compare to the documented save semantics.
Pass requires expected progress and a safe location. If the game lacks a planned
save feature, report it as missing rather than marking persistence PASS.

P07 SETTINGS PERSISTENCE
Change supported sensitivity, brightness and audio settings to identifiable
values. Verify their effects, quit, relaunch, and confirm retained values/effects.
Identify any required settings absent from the implementation as missing work.

P08 AUDIO
Listen with audio enabled at the stairs, fixtures and Sector D where accessible.
Check ambience, inspection feedback, transitions and volume balance. Merely
omitting -nosound proves only that sound was not explicitly disabled.
If no listening/recording capability exists, require a human observation.

P09 NORMAL QUIT
Use the game's Quit action. If no in-game quit flow exists, record that missing
requirement; an OS close request can be tested separately but is not equivalent.
Observe the actual game process exit and record its exit code if available.
Capture failures/hangs and fresh runtime logs when available. A missing PID or
null exit code does not prove a successful clean exit. Forced cleanup is not PASS.

P10 REPRESENTATIVE PERFORMANCE
Play the route long enough to include loading transitions and anomaly changes.
Record actual frame-time/FPS evidence with hardware and settings. Note visible
hitches. Working set and CPU accumulation are supplementary diagnostics only.
Do not invent a universal performance target; report measured results against
an agreed target, or record that no target has been agreed.
