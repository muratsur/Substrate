================================================================================
1. PRODUCT DEFINITION AND HARD CONSTRAINTS
================================================================================
Genre        Single-player atmospheric horror, first person, no combat.
Platform     PC / Steam. Engine Unreal 5.8. Price $9.99. Length 2-3 hours.
Core idea    The checklist is the horror delivery mechanism. The game tells you
             exactly what to look at; anything wrong that is NOT on the list is
             unreportable, and the shift will not close until the list is right.
Antagonist   The level geometry. No monster, no AI, no navmesh, no behaviour
             trees, no skeletal meshes, no animation blueprints.
Failure      No death screen. Failure = the shift does not close; you walk the
             route again and growth has advanced.

HARD CONSTRAINTS (every design decision must respect these)
  C1  Nothing needs AI, navmesh, animation, or skeletal assets.
  C2  Every scare is a mesh/light/door/sound state change.
  C3  Dark but LEGIBLE: the player is scored on noticing detail, so every
      checklist fixture and every anomaly site must sit in a pool of light.
  C4  Reuse: the checklist/inspection/"did the player notice" logic must be
      shareable with the sister project "Inspection Station".
  C5  Scope guardrail: vertical slice must be unsettling with placeholder
      audio or the design is wrong (gate verdict already PASSED 2026-07-29).
  C6  One person. Prefer data-driven systems over hand-built one-offs.
  C7  Blueprint-only unless a measured need forces C++.

--------------------------------------------------------------------------------
5.1 ROUND / SHIFT STATE MACHINE            owner: BP_RoundManager   [DONE+TODO]
--------------------------------------------------------------------------------
PURPOSE   Single source of truth for "where are we in the loop".
STATES
   Boot ----------> ShiftOpen ----------> AtRouteEnd ----------> Evaluating
     ^                  |  ^                                       |
     |                  |  +---- (failure: stay open, re-arm) -----+
     |                  v                                          |
     +-------------- NextRound <------ (success) ------------------+
                                                   |
                                                   v  (round == FinalRound)
                                                 Ending
TRANSITIONS
   Boot        BeginPlay: load save (5.8); if none, CurrentRound = 0.
   -> ShiftOpen   StartShift():
                    CurrentRound += 1
                    ShiftOpen = true
                    reset all fixture logs
                    run anomaly director (5.6) for this round
                    generate checklist (5.2)
                    arm growth (5.5)
                    broadcast OnShiftStarted
                    save (autosave)
   ShiftOpen -> AtRouteEnd   player enters the route-end trigger
   AtRouteEnd -> Evaluating  TryCloseShift():
                    required = rows in the checklist for this round
                    ok = every required row logged AND correct
   Evaluating -> NextRound   ok: broadcast OnShiftClosed(true); StartShift()
   Evaluating -> ShiftOpen   not ok: broadcast OnShiftClosed(false);
                             re-arm growth; keep logs; show terminal state
   NextRound -> Ending       CurrentRound == FinalRound and end condition met
FIXES REQUIRED (D2): "required rows" must come from the round's checklist
   (DT_Checklist filtered by MinRound/Sector unlocked), not "all fixtures in the
   map". Phantom rows are required to be FLAGged by absence-of-a-field: see 5.6.9.
EDGE CASES
   - Player closes the shift while standing in two triggers: debounce 1 s.
   - Save/load mid-shift: restore logs, anomalies, growth stage exactly.
   - Player never leaves a sector: nothing forces progress; the airlock gate
     (5.7) is the only gate.
TEST     T6 in IMPLEMENTATION_GUIDE.txt + load/save mid-shift (5.8).

--------------------------------------------------------------------------------
5.2 CHECKLIST GENERATION                   owner: BP_RoundManager   [TODO]
--------------------------------------------------------------------------------
PURPOSE   Decide which rows are on the terminal this round, in what order,
          with what text.
INPUT     DT_Checklist, CurrentRound, UnlockedLinks, ActiveAnomalies
ALGORITHM
   rows = []
   for r in DT_Checklist:
       if r.MinRound > CurrentRound: continue
       if r.Sector not reachable (no unlocked link path from start): continue
       rows.append(r)
   sort rows by RowOrder
   for each active anomaly of type ChecklistCorruption:
       apply to rows (5.6.9): rename a row, add a phantom row, or remove one
   assign each row a runtime state {Unlogged, PASS, FLAG}
   store as RoundChecklist (array of FRuntimeRow) on the manager
OUTPUT    RoundChecklist  -> terminal (5.9) and shift evaluation (5.1)
EDGE      A phantom row has no actor. It can never be logged by looking. Design
          decision (open, section 13): player may FLAG it from the terminal, or
          it can never be satisfied (TEST_ME.md: "unreportable since round 5").
TEST      Round 5: terminal shows the phantom row; shift behaviour matches the
          chosen rule.

--------------------------------------------------------------------------------
5.3 FIXTURE LOGGING AND VALIDATION         owner: BP_Fixture/Manager [DONE]
--------------------------------------------------------------------------------
PURPOSE   Turn "I looked at it" into PASS/FLAG and judge correctness.
DATA      FixtureState (truth): 0 nominal, 1 degraded, 2 absent.
          LogResult: 0 none, 1 PASS, 2 FLAG.
RULE      correct = (FixtureState == 0 AND LogResult == 1) OR
                    (FixtureState != 0 AND LogResult == 2)
INPUT     E -> Result 1, Q -> Result 2 (raw keys now; move to Enhanced Input).
TARGET PICK (LogLookedAtFixture)
   camera = player camera manager
   for each fixture f within cone: score = distance (else 9999)
   best = argmin score; accept if score < 400
   Cone: dot(normalize(f - eye), forward) > 0.8; range 400 uu.
IMPROVEMENTS [TODO]
   - Add line-of-sight test (a trace) so fixtures behind walls cannot be logged.
   - Absent fixtures are hidden and non-colliding: they cannot be picked.
     Provide a "log the empty mount": place an invisible BP_FixtureMount at the
     fixture location; looking at the mount allows FLAG. (Needed so absence is
     reportable. Decision D-ABS in section 13.)
   - Feedback: HUD message + soft click sound; "unlogged" = no message.
   - Allow changing a log (re-press) until shift close.
API       LogFixture(Result), ResetLog(), IsLoggedCorrectly(), ViewScore(...)
TEST      Logging matrix: 3 states x 3 results; nearest-wins; out-of-range;
          behind player (all verified except real keypress, D7).

--------------------------------------------------------------------------------
5.4 OBSERVATION SYSTEM                      owner: BPC_Observer     [TODO]
--------------------------------------------------------------------------------
PURPOSE   One reusable answer to "is X being looked at" and "how long" - used by
          growth, anomaly noticing/telemetry, scripted events, and reusable by
          Inspection Station (C4).
IMPLEMENTATION
   Component on the player pawn. Two query modes:
   (a) WasActorRecentlyRendered(actor, tolerance)  - cheap, covers occlusion
       and frustum; used by growth nodes (already in 5.5).
   (b) Cone + trace for gameplay targeting (5.3): dot > threshold AND
       LineTraceByChannel(visibility) hits the target within range.
   Timer-based, 0.2 s, never per frame.
   Maintains Dwell[actor] = seconds the actor has been in view this shift.
API       IsLooking(actor), GetDwell(actor), Noticed(actor, minSeconds)
USE       "Noticed" feeds telemetry: how many anomalies the player looked at for
          >= 1.5 s before logging; used to tune the director (section 10).

--------------------------------------------------------------------------------
5.5 GROWTH SYSTEM                           owner: BP_GrowthNode    [DONE]
--------------------------------------------------------------------------------
PURPOSE   Biomass that changes only while unobserved, once per round.
LOGIC (already implemented, see IMPLEMENTATION_GUIDE.txt 5.2)
   Every 0.2 s: if EligibleThisRound and NOT recently rendered, accumulate
   UnobservedTime; when >= SecondsToAdvance and the stage index is valid:
   swap mesh, set scale, StageIndex++, EligibleThisRound = false.
   Manager re-arms tagged nodes at StartShift and on a failed close.
TUNING TABLE (set in class defaults; per instance override allowed)
   SecondsToAdvance 4 (testbed). Production: 8-20 s so it feels like "turned
   my back", not a timer. GrowthScales 0.1 .. 1.0 (stain -> hero asset).
   Stage meshes: Alien_Biomass SM_alien_organism _01.._09.
DEFECTS   D1 tag on GrowthNode_Transit. Stage 6 has no scale (5 scales, 6 meshes).
ADDITIONS [TODO]
   - Implement BPI_Anomalous so a "Growth" anomaly can force a stage.
   - Per-node "MaxStage" so Sector C never reaches hero size before round N.
   - Persistence of StageIndex (5.8).
   - Audio: a faint cue when growth advances out of sight (optional).

--------------------------------------------------------------------------------
5.6 ANOMALY SYSTEM                      owner: BP_AnomalyDirector   [TODO]
--------------------------------------------------------------------------------
PURPOSE   The scare engine. Each round, choose and apply a small set of state
          changes the player can notice and must report.
5.6.1 DIRECTOR ALGORITHM (called from StartShift after ResetLog)
   band = DT_RoundBands.Find(CurrentRound)
   budget = RandomIntInRange(band.Budget.min, band.Budget.max)   (seeded RNG)
   pool = all DA_Anomaly where:
            MinRound <= CurrentRound <= MaxRound (or MaxRound == 0)
        AND sector reachable
        AND not used within Cooldown rounds
        AND target resolves to a live actor
        AND (not Detectable OR target is lit: light probe test)
   applied = []
   repeat budget times:
       weights[a] = band.TypeWeights[a.Type] * a.SeverityWeight
       pick a by weighted random (exclude same target twice)
       a.Apply()                      via BPI_Anomalous on the target
       applied.append(a)
       record in ActiveAnomalies (save)
       broadcast OnAnomalyApplied
   guarantee: if CurrentRound == 2 and applied is empty -> force one Absence
   (DESIGN.md: "land the first anomaly in round 2, small and deniable")
5.6.2 REVERT RULES
   EndOfShift     reverted at StartShift of the next round (before the roll)
   WhenFlagged    reverted when the player FLAGs it correctly
   Never          permanent (accumulating dread; used for Growth, Geometry)
5.6.3 THE HARDER RULE (later rounds)
   UnreportedCount += number of applied anomalies the player did not FLAG at
   close. If UnreportedCount > threshold (default 4), the director also closes
   route segments behind the player (disable a link in DT_Route) - DESIGN.md §3.
5.6.4 FAIRNESS CONSTRAINTS (so it feels earned, not cheap)
   - Every anomaly must be perceivable: target inside light, within a route
     segment the player must walk, and visible from where they would stand.
   - Never place two anomalies in the same room in rounds 2-7.
   - Light anomalies must change by >= 25% luminance or hue to be noticed.
   - Never an anomaly on a row the player cannot log (unless Phantom, 5.2).
5.6.5..5.6.14 THE TEN TYPES - how each is implemented
 #  Type            Implementation (no AI, no animation)                  Effort
 1  Growth          Force BP_GrowthNode.StageIndex +1 immediately, or set a
                    new node's mesh to stage 1 at an anomaly socket.        Low
 2  Absence         BP_Fixture.ApplyFixtureState(2) (hidden, no collision) or
                    hide any BPI_Anomalous prop (crate, sign). [DONE core]  Low
 3  Addition        Spawn/unhide a prop that was never there (a mannequin
                    stand, a stain decal, a door) from a pre-placed pool
                    of "hidden" actors tagged Anomaly_Addition.             Low
 4  Displacement    Move a tagged prop by Params.Offset (2-5 m) with a
                    small rotation; revert via stored transform.            Low
 5  Geometry        Swap an actor group: corridor segment A <-> longer
                    segment B (two pre-placed variants, one hidden), or
                    scale a module mesh on one axis; shift a door frame.   Med
 6  Light           Change a light's intensity/colour/flicker via
                    BPI_Anomalous: dead bulb (intensity 0), colour
                    temperature shift, flicker curve change.               Low
 7  Shadow          A shadow that does not match its caster: a hidden
                    "shadow proxy" static mesh (cast shadow only, hidden in
                    game) toggled on; or move a light so a shadow detaches.Low*
                    (*very effective; prioritize per DESIGN.md)
 8  Audio           Remove/mute a room-tone MetaSound source, or play a
                    sourceless sound at a point; "the room tone stops"
                    is the strongest cue.                                  Low
 9  Checklist       Terminal lists a row for a fixture that does not exist,
    corruption      renames one the player knows (text swap), or reorders.
                    Implemented in checklist generation (5.2). Needs the
                    terminal UI first.                                     Med
 10 Repetition      On leaving a room, the player's next airlock lands them
                    back in the room they just left (route table override
                    for one link, one round).                              Med
5.6.15 DATA AUTHORING WORKFLOW (how to add an anomaly in 5 minutes)
   1. Tag the target actor in the level (e.g. Anomaly_Absence).
   2. Create DA_Anomaly asset: Type, TargetTag, Sector, MinRound, weights.
   3. If the target is not a BP_Fixture, add BPI_Anomalous to its Blueprint and
      implement Apply/Revert.
   4. Add the asset to the director's registry array (or auto-scan folder).
   5. Run regression R3 (section 10) to confirm it appears and reverts.
TEST      Round 1 none; round 2 exactly one; round 2 repeated runs with the same
          seed identical; budgets honoured per band; cooldown honoured.

--------------------------------------------------------------------------------
5.7 SECTOR TRANSITIONS                  owner: BP_Airlock + route   [PARTIAL]
--------------------------------------------------------------------------------
(See also the earlier discussion: every transition is an airlock gated by the
checklist; nothing is unlocked by finding keys.)
CURRENT   Trigger -> GateOpen (rows in [GateRowMin, GateRowMax] correct) ->
          Transit() teleports to "the other airlock", disarms it, turns the
          player to the nearest fixture.
TARGET MECHANISM (data-driven)
   BP_Airlock fields: AirlockId (Name), SectorId (Name), plus the existing
   Disarmed. GateRowMin/Max are replaced by lookup in DT_Route.
   OnBeginOverlap(Player):
       if Disarmed: return
       link = DT_Route.FindByFromAirlock(AirlockId)
       if link invalid or CurrentRound < link.MinRound or link disabled:
            show "No access"; return
       if not all link.RequiredRows correct:
            show locked message with count of remaining rows; return
       BeginTransition(link)
   BeginTransition(link):
       1  lock player input (movement + look) 0.3 s
       2  fade to black over link.FadeSeconds (WBP_FadeOverlay)
       3  play airlock door sound (cycle) - hides streaming/teleport
       4  dest = airlock with AirlockId == link.ToAirlock
       5  if streaming: LoadStreamLevel(dest sector), wait until loaded;
          UnloadStreamLevel(origin sector) after the fade is complete
       6  SetActorLocation(player, dest) ; face dest.ArrivalDirection (or
          nearest fixture as fallback)
       7  Disarm dest until the player leaves it
       8  switch grade: activate dest sector's PPV/fog/room tone
          (BP_SectorVolume.OnEnter) ; broadcast OnSectorEntered
       9  fade in ; unlock input
   ARRIVAL FACING: store ArrivalYaw on each airlock (no more "nearest fixture"
   heuristic once sector layouts are final).
TRANSITION KINDS (choose per link, DT_Route.Kind)
   Teleport       one map, spatially separate areas (current)
   Stream         sub-level swap behind the fade (full game)
   Walk           true walkable connection (only if a sector is seamless)
   Mutate         same physical door, different destination this round
                  (Repetition / "facility is larger than you were told")
PERFORMANCE   Teleport-in-one-map is fine for the demo (A-C). For D-F use
   level streaming: each sector is a sub-level; only current + next loaded.
EDGE CASES
   - Falling into a canal (BP_CanalRescue) must not leave the player in an
     unloaded sector: rescue teleports to the current sector's RespawnPoint.
   - Player at the airlock while the round changes: re-evaluate gate.
   - Two players? Not supported.

5.12 LIGHTING AND POST-PROCESS PIPELINE         owner: art/tech     [PARTIAL]
--------------------------------------------------------------------------------
PRINCIPLES (DESIGN.md §8)

      every attempt to darken.
   2. Dark but legible: crushed blacks in negative space; every fixture inside
      a pool of motivated light.
   3. The player never sees more than ~15 m of corridor (fog/geometry breaks).
   4. Practical lights are level design: each checklist fixture has its own
      light; the route is a chain of lit islands connected by dark.
GLOBAL BASELINE (current values, L_SectorC)
   Directional 0.5 cold blue (0.62,0.78,1.0) ; Sky 0.45
   Fog density 0.28, inscattering (0.011,0.017,0.021), volumetric albedo
   (0.42,0.48,0.55), extinction 1.1
   Global PPV (unbound): exposure min=max=0.55, bias -1.5, saturation 0.8,
   vignette 0.55, bloom 0.1

   priority above the global. Table (target look; tune in Play):
   Sector  Mood             Bias   Saturation   Fog colour       Key light

14. APPENDIX - PSEUDOCODE LIBRARY AND NODE CHEAT-SHEET
================================================================================
14.1 StartShift (target)
   CurrentRound += 1
   ShiftOpen = true
   RevertAnomalies(EndOfShift)
   ResetAllFixtureLogs()
   Director.RollAnomalies(CurrentRound, Seed)
   Checklist = GenerateChecklist(CurrentRound)
   ArmGrowth()
   Broadcast OnShiftStarted(CurrentRound)
   AutoSave()

14.2 TryCloseShift (target)
   if not ShiftOpen: return
   required = Checklist.rows where not Phantom
   ok = all(row.fixture.IsLoggedCorrectly for row in required)
   if ok:
       UnreportedCount = max(0, UnreportedCount - 1)
       Broadcast OnShiftClosed(true)
       if CurrentRound >= EndRound and EndCondition: Ending()
       else: StartShift()
   else:
       UnreportedCount += count(applied anomalies not FLAGged)
       ArmGrowth()
       Broadcast OnShiftClosed(false)

14.3 Airlock.OnBeginOverlap (target)
   if Disarmed or not IsPlayer(other): return
   link = Route.FindFrom(AirlockId)
   if not Route.IsAvailable(link, CurrentRound): Hud("No access"); return
   missing = link.RequiredRows.filter(not logged correct)
   if missing.length > 0: Hud("Locked - " + missing.length + " remaining"); return
   BeginTransition(link)

14.4 Director.ChooseAnomaly (weighted pick)
   total = sum(w(a) for a in pool)
   r = RandomFloat(0, total)
   for a in pool: r -= w(a); if r <= 0: return a

14.5 Blueprint patterns that worked
   - Keep For Each bodies tiny: Cast -> call a function on the cast object.
   - Prefer functions with clear inputs/outputs over big event graphs.
   - Timers via "Set Timer by Function Name" with Looping.
   - Use "Get All Actors With Tag" once and cache in BeginPlay.
   - Never edit the recovered BP_FirstPersonCharacter; subclass it.
