2. ROOT CAUSE & DEPENDENCY AUDIT
================================================================================
- Root Cause Analysis:
  1. Engine Plugin Definition:
     C:\Program Files\Epic Games\UE_5.8\Engine\Plugins\Runtime\HoudiniEngine\HoudiniEngine.uplugin
     declares "EnabledByDefault": true and defines a module "HoudiniEngineRuntime"
     with "Type": "Runtime".
  2. Missing Engine Shipping Binary:
     The engine directory at Engine\Plugins\Runtime\HoudiniEngine\Binaries\Win64
     contains ONLY editor binaries:
       - UnrealEditor-HoudiniEngine.dll
       - UnrealEditor-HoudiniEngineEditor.dll
       - UnrealEditor-HoudiniEngineRuntime.dll
       - UnrealEditor.modules
     There was NEVER an UnrealGame-Win64-Shipping-HoudiniEngineRuntime.dll provided
     with the installed engine.
  3. Game Dependency Check:
     An exhaustive audit of Config/, Content/, and L_SectorC.umap confirmed:
       - Zero Houdini actors or components exist in any map or Blueprint.
       - Zero assets reference /Script/HoudiniEngineRuntime.
       - The game project does not use Houdini at runtime; Houdini was authoring-only.
  4. Packaging Inheritance:
     Generic content-only packaging inherited the engine's EnabledByDefault=true,
     requesting HoudiniEngineRuntime in the cooked package manifest. When launched,
     UnrealGame-Win64-Shipping.exe attempted to load the nonexistent shipping DLL
     and halted on the modal MessageBox.
  5. Harness Flaw Discovered:
     The prior smoke test harness checked only `proc.poll() is None`. Because a
     modal MessageBox keeps the host process alive, the previous test reported
     "PASS (Running healthy)" on a completely blocked application.
