1. WHAT THE GAME IS
================================================================================
Single-player atmospheric horror, PC (Steam), Unreal Engine 5.8.
You are a maintenance technician. Each "shift" you walk a fixed route, look at
a fixed list of fixtures, log each one PASS or FLAG, and close the shift.
Biomass ("growth") advances only while you are not looking at it, at most once
per round. There is no monster: the level geometry is the antagonist.
Failure is not a death screen - it is the shift not closing, so you walk the
route again while the growth advances.
(Full design: DESIGN.md. Test notes: TEST_ME.md.)

The core loop implemented so far:
   start in the sewer (Sector C)
   -> look at a fixture, press E (PASS) or Q (FLAG)
   -> log all five sewer fixtures
   -> the dock airlock unlocks and teleports you to the Transit corridor
   -> log the three Transit fixtures
   -> the Transit airlock unlocks and sends you back
   -> walk into the round-manager trigger to try to close the shift
   -> all correct: next round (growth re-armed), otherwise shift stays open.

5. BLUEPRINTS - EXACT BUILD
================================================================================
General rules used everywhere:
  - All four gameplay Blueprints have parent class "Actor".
  - Create them in /Game/Substrate/Core/ with EXACTLY these names. The map
    stores the class paths (/Game/Substrate/Core/BP_Fixture etc.); a different
    name or folder breaks every placed instance.
  - "Get All Actors Of Class" + "For Each Loop" + "Cast To BP_Fixture" is the
    pattern used. Keep loop bodies simple (call a small function on the cast
    object) - it is easier to read and debug.
  - Compile (F7) after each function.

--------------------------------------------------------------------------------
5.1  BP_Fixture   (a checklist item the player looks at)
--------------------------------------------------------------------------------
Parent: Actor.
Components: StaticMeshComponent named "StaticMeshComponent" as the ROOT
  (drag it onto DefaultSceneRoot to replace it).
Variables (all Instance Editable):
  FixtureID    Name       checklist label, e.g. "C-01 INLET VALVE"
  RowOrder     Integer    0-based checklist row
  FixtureState Integer    0 nominal, 1 degraded, 2 absent
  LogResult    Integer    0 unlogged, 1 PASS, 2 FLAG

Functions:
  ApplyFixtureState (Input: NewState Integer)
    Set FixtureState = NewState
    Set Actor Hidden In Game (Target Self, New Hidden = NewState == 2)
    Set Actor Enable Collision (Target Self, New Actor Enable Collision =
        NewState != 2)
  LogFixture (Input: Result Integer)
    Set LogResult = Result
    Print String( ToString(FixtureID) + (Result == 1 ? ": PASS" : ": FLAG"),
        Duration 3.0 )      <- on-screen feedback; also written to the log
                               category LogBlueprintUserMessages
  ResetLog
    Set LogResult = 0
  IsLoggedCorrectly (Output: Correct Boolean)
    Expected = Select Int (A: 1, B: 2, Pick A = FixtureState == 0)
    Return Correct = (LogResult == Expected)
    (nominal fixture must be PASS; degraded or absent must be FLAG)
  ViewScore (Inputs: EyeLocation Vector, ViewForward Vector; Output: Score Float)
    Delta = GetActorLocation(Self) - EyeLocation
    Return Score = Select Float( A: VectorLength(Delta), B: 9999.0,
        Pick A = DotProduct(Normalize(Delta), ViewForward) > 0.8 )
    (distance if inside a ~37 degree cone of the view direction, else huge)
  DistanceFrom (Input: Point Vector; Output: Dist Float)
    Return Dist = Distance(GetActorLocation(Self), Point)
  HasIdPrefix (Input: Prefix String; Output: Matches Boolean)
    Return Matches = StartsWith( ToString(FixtureID), Prefix )
    (kept for reference - the airlock gate now uses InRowRange)
  InRowRange (Inputs: MinRow, MaxRow Integer; Output: InRange Boolean)
    Return InRange = (RowOrder >= MinRow) AND (RowOrder <= MaxRow)

Event Graph:
  Event BeginPlay -> ApplyFixtureState(NewState = FixtureState)
  (applies the placed state; set FixtureState on the placed instance to make an
   anomaly.)

--------------------------------------------------------------------------------
5.2  BP_GrowthNode   (biomass that advances only while unobserved)
--------------------------------------------------------------------------------
Parent: Actor.
Components: StaticMeshComponent named "StaticMeshComponent" as ROOT.
Variables:
  GrowthStages      Array of Static Mesh   (Instance Editable)
  GrowthScales      Array of Float         (Instance Editable)
  SecondsToAdvance  Float                  (Instance Editable)
  EligibleThisRound Boolean   latch: may advance this round
  StageIndex        Integer   number of advances done (index into the arrays)
  UnobservedTime    Float     seconds continuously unobserved
Class defaults currently set:
  SecondsToAdvance = 4
  GrowthScales     = 0.1, 0.25, 0.4, 0.55, 0.75, 1.0   (6 values, 1 per stage)
  GrowthStages     = SM_alien_organism_02, _01, _03, _04, _05, _06

Event Graph:
  Event BeginPlay
    Set EligibleThisRound = true
    Set Timer by Function Name (Object: Self, Function Name: "CheckObserved",
        Time: 0.2, Looping: true)

Function CheckObserved:
  Branch (EligibleThisRound)
    true:
      Branch (Was Actor Recently Rendered(Target Self, Tolerance 0.2))
        true  (being looked at): Set UnobservedTime = 0.0
        false (unobserved):
          Set UnobservedTime = UnobservedTime + 0.2
          Branch (UnobservedTime >= SecondsToAdvance)
            true:
              Branch (Is Valid Index(GrowthStages, StageIndex))
                true:
                  Set Static Mesh (Target StaticMeshComponent,
                      New Mesh = Get(GrowthStages, StageIndex))
                  Branch (Is Valid Index(GrowthScales, StageIndex))
                    true: Set Actor Scale 3D (Self,
                        X=Y=Z=Get(GrowthScales, StageIndex))
                  Set StageIndex = StageIndex + 1
                  Set EligibleThisRound = false     <- the once-per-round latch
                  Set UnobservedTime = 0.0
  IMPORTANT: the IsValidIndex check on GrowthScales matters - "Get" on an
  out-of-range array index returns 0 and would scale the growth to nothing.
Why "once per round": see DESIGN.md section 4 (unlatched growth runs its whole
ladder in ~15 s and becomes a timer to wait out).

--------------------------------------------------------------------------------
5.3  BP_RoundManager   (round counter, shift close, player logging input)
--------------------------------------------------------------------------------
Parent: Actor.
Components:
  Box Collision named "CollisionComponent" as ROOT (default extent 32,32,32)
  Billboard named "SpriteComponent"
Variables:
  RouteStart   Vector    (Instance Editable)  placed value (0, 1400, 360)
  CurrentRound Integer   starts 0
  ShiftOpen    Boolean
  RequiredRowMax Integer (Instance Editable) highest RowOrder the shift needs;
                         default 7 (row 8 = C-06 is Sector D, not required yet)
  AllCorrect   Boolean   scratch for TryCloseShift
  BestDist     Float     scratch for LogLookedAtFixture
  BestFixture  Object reference: BP_Fixture   scratch

Functions:
  ArmGrowth
    Get All Actors With Tag("Growth") -> For Each
      Cast To BP_GrowthNode -> Set EligibleThisRound = true
  StartShift
    Set CurrentRound = CurrentRound + 1
    Set ShiftOpen = true
    Get All Actors Of Class(BP_Fixture) -> For Each -> Cast To BP_Fixture ->
        ResetLog
    Call ArmGrowth
  TryCloseShift
    Branch (ShiftOpen)
      Set AllCorrect = true
      Get All Actors Of Class(BP_Fixture) -> For Each -> Cast To BP_Fixture:
          inPlay = InRowRange(fixture, 0, RequiredRowMax)
          correct = IsLoggedCorrectly(fixture)
          if inPlay AND NOT correct: Set AllCorrect = false
      Branch (AllCorrect)
        true:  Call StartShift     (next round)
        false: Call ArmGrowth      (shift stays open; growth re-armed =
                                    "failure means more exposure")
  LogLookedAtFixture (Input: Result Integer)
    Set BestDist = 400.0
    Get All Actors Of Class(BP_Fixture) -> For Each -> Cast To BP_Fixture:
      Score = ViewScore(fixture, EyeLocation = GetCameraLocation(
                  GetPlayerCameraManager(0)),
              ViewForward = GetForwardVector(GetCameraRotation(
                  GetPlayerCameraManager(0))))
      Branch (Score < BestDist): Set BestDist = Score; Set BestFixture = fixture
    Branch (BestDist < 400.0):
        true:  BestFixture -> LogFixture(Result)
        false: Print String("Nothing in range - look at a fixture, get within
                4 m", Duration 2.0)
    (= nearest fixture within 400 units and ~37 degrees of the camera)

Event Graph:
  Event BeginPlay
    Call StartShift
    Enable Input (Player Controller = Get Player Controller(0))
  Event ActorBeginOverlap (Other Actor)
    Cast To Character (Object = Other Actor) -> Call TryCloseShift
  Input Key E  -> Pressed -> LogLookedAtFixture(Result = 1)    (PASS)
  Input Key Q  -> Pressed -> LogLookedAtFixture(Result = 2)    (FLAG)
  (Key nodes: right-click the graph, type "E" under Input -> Keyboard Events.)
  If the game uses Enhanced Input for these later, replace the key nodes with
  new Input Actions IA_Pass / IA_Flag and map E / Q in IMC_Default.

--------------------------------------------------------------------------------
5.4  BP_Airlock   (paired teleporters, locked by checklist progress)
--------------------------------------------------------------------------------
Parent: Actor.
Components:
  Box Collision named "CollisionComp" as ROOT (extent 32,32,32 - make it larger
      if you want it easier to enter)
  Billboard named "Sprite"
Variables:
  Disarmed     Boolean   true on the arrival airlock so you are not bounced back
  GateRowMin   Integer   (Instance Editable)  first checklist row required
  GateRowMax   Integer   (Instance Editable)  last checklist row required
  GateOK       Boolean   scratch
  Pending      Integer   scratch: how many required fixtures are not yet correct
  NearestDist  Float     scratch
  NearestLoc   Vector    scratch

Functions:
  GateOpen
    Set GateOK = true; Set Pending = 0
    Get All Actors Of Class(BP_Fixture) -> For Each -> Cast To BP_Fixture:
      inRange = InRowRange(fixture, GateRowMin, GateRowMax)
      correct = IsLoggedCorrectly(fixture)
      Branch (inRange AND NOT correct): Set GateOK = false; Pending = Pending + 1
  Disarm
    Set Disarmed = true
  FaceNearestFixture (Input: Traveler Actor)
    Set NearestDist = 1000000.0
    Here = GetActorLocation(Self)
    For Each BP_Fixture: d = DistanceFrom(fixture, Here);
        if d < NearestDist: NearestDist = d; NearestLoc = fixture location
    Cast To Pawn (Traveler) -> Pawn -> Set Control Rotation(
        Controller = GetController(pawn),
        New Rotation = MakeRotator(Roll 0, Pitch 0,
                       Yaw = FindLookAtRotation(Here, NearestLoc).Yaw))
    (without this the player arrives facing the wrong way and sees only sky)
  Transit (Input: Traveler Actor)
    Get All Actors Of Class(BP_Airlock) -> For Each element:
      Branch (element != Self):
        Cast To BP_Airlock (element)
        Call Disarm on it
        Set Actor Location (Traveler, element location)
        Call FaceNearestFixture(Traveler) on the cast object

Event Graph:
  Event ActorBeginOverlap (Other Actor)
    Cast To Character (Other Actor)
    Branch (NOT Disarmed)
      Call GateOpen
      Branch (GateOK)
        true:  Call Transit(Traveler = Other Actor)
        false: Print String("Airlock locked - log the fixtures on this side
               first (E = PASS, Q = FLAG)", Duration 4.0)
  Event ActorEndOverlap
    Set Disarmed = false

Placed values (see section 6): dock airlock rows 0-4, Transit airlock rows 5-7.

7. LIGHTING AND POST-PROCESS - EXACT VALUES
================================================================================
Goal (DESIGN.md section 8): "dark but legible" - crushed blacks in negative
space, every checklist fixture sitting in a pool of motivated light.

DirectionalLight   Intensity 0.5   Colour (0.62, 0.78, 1.0)
SkyLight           Intensity 0.45
ExponentialHeightFog (ExponentialHeightFog_1)
                   FogDensity 0.28
                   FogInscatteringLuminance (0.011, 0.017, 0.021)
                   VolumetricFog ON, Albedo (0.42, 0.48, 0.55),
                   ExtinctionScale 1.1, HeightFalloff 0.673
PostProcessVolume_1  (Unbound = true, Priority 0)   <- the main grade
                   Auto Exposure Method: Histogram
                   Min Brightness 0.55, Max Brightness 0.55   (LOCKED)
                   Exposure Bias -1.5   (was +1; lowered so it is not white)
                   Color Saturation 0.8, Vignette 0.55, Bloom 0.1
PostProcessVolume_0  (bounded, Priority 10, at (-440, -8600, 400) = Sector D)
                   Exposure Bias -1.6, Saturation (0.6, 0.55, 0.55),
                   Vignette 0.7, Bloom 0.675, same locked 0.55 brightness
PostProcessVolume_3  (bounded, at (-802, 807, 132)) bloom/colour tweaks only

HOW EXPOSURE WORKS HERE (read this before touching lights)
  Because the exposure is locked to 0.55, lights must be small. A 900 cd point
  light 4 m above a surface is far too strong at that exposure unless the bias is
  pulled down. If a scene looks white:
    1. Lower PostProcessVolume_1 > Exposure Bias (try -1.5, then -2.5).
    2. Or lower light intensities.
    3. Surface colours matter least (see section 8).
  Always change one thing at a time and press Play to judge - the editor
  viewport and PIE can look different.

10. HOW TO TEST EVERY FEATURE (step by step)
================================================================================
Always: open L_SectorC, press Play (Alt+P). Shift+F1 frees the mouse.

T1  Map loads clean
    Window -> Message Log -> Load Errors = 0.

T2  Spawn / look
    You start at (0, 1400, 360) facing +Y in the sewer. It should be dark blue
    and green, with your lights visible. If it is white: section 7.

T3  Logging

11. GIT WORKFLOW AND THE MISTAKES TO AVOID
================================================================================
Branches: main is protected by habit - work on a branch, open a PR, merge on
GitHub, then pull. Open PR: #2 (branch post-merge-fixes). PR #1 is merged.

Commands (PowerShell, one at a time):
  git status
  git checkout -b my-branch
  git add Content/Substrate/Core/BP_Fixture.uasset
  git commit -m "message"
  git push -u origin my-branch
  (open the PR on GitHub, merge it there)
  git checkout main
  git pull origin main

RULES (each one cost real time in this project)
  1. CLOSE UNREAL before switching branches. Open assets are locked and git
     fails to unlink them ("Unlink of file ... failed").
  2. MERGE THE PR BEFORE checking out main. Files only on the branch are deleted
     from disk when you switch.
  3. NEVER click "Save All" or "Save Selected" on L_SectorC while it has load
     errors or unexpected changes - saving strips broken references forever.
     Use "Don't Save" on stray prompts (BP_CanalRescue just shows modified after
     a recompile).
  4. Save only the assets you changed (Content Browser -> right-click -> Save).
  5. Binary .uasset/.umap files cannot be merged. Do not edit the same asset on
     two branches.
  6. Content/Characters is not tracked (126 MB). Restore from the template.
  7. If Windows says "unable to unlink", move the stray files aside, do not
     delete them.
  8. A change made in the editor but not saved is LOST when you click
     "Don't Save" - save the asset first if you want to keep it.
